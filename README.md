# 한칸이야기 설계 문서

아이가 사람을 그려 올리면 그 그림이 캐릭터가 되고, 아이가 **장소 · 문제 · 행동 · 결과** 네 칸을
직접 골라 움직이는 이야기를 만드는 웹앱의 설계 문서 모음이다.

| 항목 | 내용 |
|---|---|
| 앱 표시명 | **한칸이야기** |
| 과제명 | 발달장애·학습지원 아동을 위한 그림 기반 참여형 이야기 구성 AI |
| 영문 표기 | DrawTale (저장소 이름) · StoryBlanks (앱 내부 식별자) |
| 대상 | 시각적·단계적 지원이 필요한 아동. 계정은 보호자·교사의 것이다 |
| 기준 플랫폼 | 웹 / 태블릿 가로 1024×768 기준, 세로·데스크톱 대응 |
| 문서 기준일 | 2026-09-30 |

## 이 서비스의 첫 번째 원칙

> **AI가 동화를 대신 만들어 주는 서비스가 아니다. 이야기를 구성하는 주체는 아이다.**

AI는 아이가 고른 네 칸을 문장으로 다듬고, 아이 그림을 움직이게 하는 일만 한다.
기능을 더하거나 화면 문구를 정할 때 이 문장을 기준으로 삼는다.

아이 화면에는 `발달장애` `특수교육` `장애` `진단` `치료` 같은 말과 기술 용어를 쓰지 않는다.
과제명과 기획서에서는 대상을 분명히 밝히되, 아이가 매일 여는 화면에 진단명이 적혀 있으면
그 자체가 낙인이 된다.

## 용어

| 용어 | 뜻 |
|---|---|
| 캐릭터 | 아이가 그린 사람 모양 그림 하나. 한 이야기에 한 명이다 |
| 관절 | 캐릭터를 움직이는 점 15개 (`hip` `torso` `neck` 어깨·팔꿈치·손 양쪽, 골반·무릎·발 양쪽). 좌표는 원본 그림의 픽셀 기준 |
| 마스크 | 그림에서 캐릭터 영역만 남긴 흑백 이미지. 렌더할 때 이 영역만 움직인다 |
| 분석 | 그림에서 캐릭터를 찾고 관절과 마스크를 만드는 일. AI 서버가 한다 |
| 렌더 | 관절과 마스크로 캐릭터가 움직이는 MP4를 만드는 일. AI 서버가 한다 |
| 네 칸 | 이야기의 네 단계. 장소 → 문제 → 행동 → 결과 순서가 고정이다 |
| 말로 덧붙이기 | 카드를 고른 뒤 아이가 마이크로 한마디 더하는 기능. 어른 설정에서 켜야 한다 |
| 순화 동작 | 팔 회전을 줄이고 팔꿈치를 거의 편 동작(`wave_hello_gentle` `jumping_gentle`). 팔을 몸에 붙여 그린 그림에서 팔이 뭉개지지 않게 한다 |
| Job | 오래 걸리는 서버 작업(분석, 이야기 생성) 하나. 프론트는 상태를 1.5초마다 묻는다 |
| 지원 수준 | Level 1·2·3. 한 화면의 선택지 수, 아이콘 크기, 글자 표시, 음성 자동 재생이 달라진다 |
| 비회원 체험 | 로그인 없이 기기당 2편까지 만들 수 있다. 이야기는 탭을 닫으면 사라진다 |
| 목 엔진 | 서버 없이 프론트만으로 흐름을 끝까지 돌리는 가짜 엔진 (`VITE_ENGINE=mock`) |

## 문서를 고칠 때

1. 코드나 계약이 바뀌면 **같은 날 해당 문서를 고친다.** 문서가 코드보다 뒤처지면 팀원은 문서를 믿고 잘못 만든다
2. 기능을 더하면 02에 기능 ID를 먼저 만들고, 04에 화면 요소를, 03에 흐름을 넣는다
3. 아직 정하지 않은 것은 각 문서의 「아직 정하지 않은 것」 표에 적는다. 추측으로 채우지 않는다
4. 아래 버전 기록에 한 줄을 남긴다
