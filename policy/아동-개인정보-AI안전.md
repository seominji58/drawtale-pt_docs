# 아동 · 청소년 개인정보와 AI 안전 설계

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (초안) |
| 작성일 | 2026-10-12 |
| 근거 확인일 | **2026-10-12** |
| 상태 | **출시 전 법률 · 개인정보 전문가 검토 필요** |

> **이 문서는 무엇인가**
>
> DrawTale 은 만 14세 미만 아동이 쓰는 서비스입니다.
> 이 문서는 **아이의 개인정보를 어떻게 다루고, AI 를 어떻게 안전하게 쓸지** 정합니다.
> 데이터가 어디로 가는지는 [데이터 처리 지도](데이터-처리-지도.md),
> 이야기를 안전하게 만드는 방법은 [이야기 안전 정책](이야기-안전-정책.md)에 있습니다.

**이 문서는 법률 자문이 아닙니다.** 확인한 법령과 플랫폼 정책을 바탕으로 위험을 줄이는
방향을 적은 것이며, **출시 전에 전문가 검토를 받아야 합니다.**

표시 약속:

| 표시 | 뜻 |
|---|---|
| **[법적 요구사항]** | 법령에서 확인되는 의무 |
| **[OpenAI 정책]** | OpenAI 가 개발자에게 요구하는 것 |
| **[DrawTale 설계 선택]** | 법이 강제하지 않지만 우리가 택한 것 |
| **[법률 검토 필요]** | 개발자가 임의로 정하면 안 되는 것 |

## 1. 지금 구조에서 가장 큰 위험 세 가지

현재 설계([01 요구사항 정의서](../01-requirements.md) ~ [09 DB ERD](../09-db-erd.md))를 놓고 보면
아래 세 가지가 가장 급합니다.

### 1-1. 아이가 말로 덧붙인 내용이 OpenAI 로 갑니다

`F-STY-02`(말로 덧붙이기)로 아이가 한마디를 더하면, 그 글자가 이야기 생성 요청에 함께 들어갑니다.
아이가 **"내 이름은 ○○이야"** 라고 말하면 그대로 외부로 나갑니다.

> **[OpenAI 정책]** OpenAI Under-18 API Guidance 는
> **만 13세 미만 또는 해당 지역의 디지털 동의 연령 미만 아동의 개인정보를 API 로 보내려면
> Zero Data Retention 을 먼저 적용하라**고 안내합니다.
> 한국의 디지털 동의 연령은 **만 14세**이므로(개인정보 보호법 제22조의2),
> **만 14세 미만 아동의 개인정보를 OpenAI 로 보내는 구조는 ZDR 없이 기본안으로 삼지 않습니다.**

**[DrawTale 설계 선택]** 가장 보수적인 기본안을 택합니다 —
**아이의 직접 식별 정보를 OpenAI 로 보내지 않습니다.**
아이가 말한 내용은 보내기 전에 걸러냅니다 (3-3).

### 1-2. 아이 계정과 보호자 계정이 구분되지 않습니다

지금은 `users` 하나뿐이고, 아이를 나타내는 자리가 없습니다.
`characters.user_id` 는 **올린 계정**을 가리킬 뿐, 그 그림이 어느 아이 것인지 모릅니다.

그래서 보호자가 **"우리 아이 자료만 지워 주세요"** 라고 했을 때 골라낼 수 없습니다.

### 1-3. 생성형 AI 표시 의무가 이미 시행 중입니다

> **[법적 요구사항]** 인공지능기본법 제31조 제2항은
> 생성형 AI 로 만든 결과물에 **그 사실을 표시하도록** 정하고 있고,
> **2026년 1월 22일 시행되었습니다.**
> 시행령은 표시를 사람이 인식할 수 있는 방법 또는 기계가 판독할 수 있는 방법으로 하되,
> **주된 이용자의 나이와 신체적 · 사회적 조건을 고려**하도록 하고 있습니다.

DrawTale 은 이야기 문장과 읽어 주는 음성을 생성형 AI 로 만듭니다.
**지금 화면에는 그 표시가 없습니다.**

## 2. 계정 구조 — 보호자 계정 아래 아이 프로필

### 2-1. 아이는 가입하지 않습니다

**[DrawTale 설계 선택]** 아이에게 이메일 · 비밀번호 · 전화번호 · 소셜 로그인을 요구하지 않습니다.
보호자 또는 교사가 계정을 만들고, 그 아래에 **아이 프로필**을 둡니다.

```
보호자 · 교사 계정 (users)
   └── 아이 프로필 (child_profiles)       ← 새로 둔다
          └── 그림 · 이야기 · 활동 기록
```

이 구조는 지금 `users` 설계와 어긋나지 않습니다.
`users` 에는 이미 아이에 관한 칸이 하나도 없습니다.

### 2-2. 아이 프로필에 무엇을 둘까

**필요한 것만 둡니다.** 개인정보 보호법 제16조(최소 수집)를 따릅니다.

| 둔다 | 왜 |
|---|---|
| 프로필 id | 자료를 묶기 위해 |
| **부르는 이름** (별명) | 화면에 보여 주기 위해. **실명을 권하지 않습니다** |
| 이야기 난이도 설정 | 지금의 지원 수준(`F-SET-02`)이 여기로 옮겨옵니다 |
| 보호자 계정 연결 | 누구의 아이인지 |

| 두지 않는다 | 왜 |
|---|---|
| **정확한 생년월일** | 아래 2-3 |
| 실명 · 성별 · 학교 · 주소 · 연락처 | 서비스에 필요하지 않습니다 |
| 진단명 · 장애 유형 | **민감정보입니다. 서비스에 필요하지 않습니다** |

> **[DrawTale 설계 선택]** 별명은 **아이의 실제 이름이 아닌 것을 권합니다.**
> 화면에 "○○아, 잘했어!" 같은 문구를 쓰려면 부를 이름이 필요한데,
> 실명이 아니어도 그 목적은 충족됩니다. 입력 화면에서 그렇게 안내합니다.

### 2-3. 나이는 어떻게 다룰까

**"만 14세 미만인지 아는 것"** 과 **"생년월일을 저장하는 것"** 은 다릅니다.

| 방법 | 저장하는 것 |
|---|---|
| **[DrawTale 설계 선택]** 보호자에게 **「만 14세 미만입니까?」만 묻는다** | 참/거짓 한 칸 |
| (대안) 출생연도만 받는다 | 연도 하나 |
| (쓰지 않음) 생년월일 전체 | — |

> **[법률 검토 필요]** 참/거짓 한 칸만으로 **법 제22조의2의 「확인」 의무를 충족하는지**
> 전문가 확인이 필요합니다. 이 항목은 동의 확인 방법(3-2)과 함께 검토해야 합니다.

**주민등록번호는 받지 않습니다.** 법이 정한 경우가 아니면 처리할 수 없고,
DrawTale 에는 그런 근거가 없습니다.

## 3. 만 14세 미만 법정대리인 동의

### 3-1. 계정 가입과 아동 개인정보 동의는 다릅니다

> **[법적 요구사항]** 개인정보 보호법 제22조의2 제1항은
> 만 14세 미만 아동의 개인정보를 동의에 근거해 처리하려면
> **법정대리인의 동의를 받고, 그 동의가 이루어졌는지 확인**하도록 정하고 있습니다.
> 제2항은 그 동의를 받기 위해 필요한 **최소한의 정보는 아동에게서 직접 받을 수 있다**고 하며,
> 시행령은 그 범위를 **법정대리인의 성명과 연락처**로 한정합니다.
> 제3항은 아동에게 알릴 때 **이해하기 쉬운 양식과 명확하고 알기 쉬운 언어**를 쓰도록 합니다.

**「보호자 계정으로 가입했으니 동의한 것으로 본다」로 처리하지 않습니다.**
계정을 만드는 것과 아이 개인정보 처리에 동의하는 것은 별개입니다.

### 3-2. 동의 흐름

```
보호자가 계정을 만든다 (카카오 · 구글)
        │
        ▼
「아이 프로필 만들기」
        │
        ▼
아동 개인정보 수집 · 이용 안내를 보여 준다
  무엇을 받는지 · 왜 받는지 · 얼마나 두는지 · 어디로 보내는지
        │
        ▼
법정대리인 동의 (필수 항목과 선택 항목을 나눈다)
        │
        ▼
동의 사실 확인                    ← [법률 검토 필요]
        │
        ▼
아이 프로필이 쓸 수 있게 된다
```

> **[법률 검토 필요]** **동의 확인 방법을 임의로 정하지 않습니다.**
> 시행령과 개인정보보호위원회 가이드라인에서 문자메시지 · 신용카드 · 본인확인 등이
> 거론되지만, **DrawTale 에 어느 방법이 충분한지는 전문가 확인이 필요합니다.**
> 확정 전까지는 설계에 **확인 단계가 있다는 것만** 두고 방법은 비워 둡니다.

### 3-3. 동의 기록

**[법적 요구사항]** 동의를 받았다는 사실을 나중에 확인할 수 있어야 합니다.

| 남긴다 | 남기지 않는다 |
|---|---|
| 누가 (보호자 계정 id) | **주민등록번호** |
| 누구에 대해 (아이 프로필 id) | 신분증 사본 |
| 무엇에 (동의 종류) | 보호자 실명 (소셜 로그인에서 받지 않습니다) |
| 어느 판에 (약관 버전) | |
| 언제 (동의 시각 · 철회 시각) | |
| 어떻게 확인했는지 (방법 이름만) | |

표 구조는 [DB 변경 제안](#8-db--코드에-필요한-최소-변경)에 있습니다.

## 4. 보호자가 할 수 있어야 하는 일

> **[법적 요구사항]** 개인정보 보호법 제38조는 정보주체와 법정대리인이
> 열람 · 정정 · 삭제 · 처리정지를 요구할 수 있도록 하고 있습니다.

보호자 화면에서 아래가 가능해야 합니다.

| 할 수 있어야 하는 일 | 지금 상태 |
|---|---|
| 어떤 정보를 저장하고 있는지 본다 | **없음** |
| 동의를 철회한다 | **없음** |
| 아이 프로필을 지운다 | **없음** |
| 올린 그림 원본을 지운다 | 있음 (`F-SET-04`) |
| 만든 이야기를 지운다 | 있음 (`F-LIB-02`, 기기에서만) |

### 지울 때 무엇이 함께 지워지나

```
보호자 계정을 지우면
   └ 아이 프로필 전부
        └ 그림 · 관절 보정 이력
             └ 이야기 · 음성 · 영상
                  └ 활동 기록
        └ 작업 기록
   └ 소셜 연결 · 로그인 값
   └ 동의 기록        ← 아래 참고
```

**동의 기록은 생각해 볼 부분이 있습니다.**
자료를 다 지웠는데 "동의를 받았다"는 기록만 남기는 것이 맞는지,
아니면 그것도 지우는 것이 맞는지 판단이 필요합니다.

> **[법률 검토 필요]** 동의 철회 · 계정 삭제 뒤
> **동의 기록을 얼마나 보관해야 하는지**(또는 보관하면 안 되는지) 확인이 필요합니다.

### CASCADE 를 다시 봅니다

지금 모든 외래 키가 `ON DELETE CASCADE` 입니다 ([09 DB ERD](../09-db-erd.md) 5장).
아래는 삭제 의도가 실제로 맞는지 정리한 것입니다.

| 지우면 | 함께 지워진다 | 맞나 |
|---|---|---|
| 보호자 계정 | 아이 프로필 · 그 아래 전부 | **맞습니다.** 탈퇴하면 남는 것이 없어야 합니다 |
| 아이 프로필 | 그 아이의 그림 · 이야기 · 활동 기록 | **맞습니다.** 이것이 보호자가 요구하는 삭제입니다 |
| 그림 | 관절 보정 이력 · **이야기** | **다시 봐야 합니다** — 아래 |
| 이야기 | 활동 기록 | 맞습니다 |

**그림을 지우면 이야기까지 지울지**가 걸립니다.
지금 「원본 그림 지우기」(`F-SET-04`)는 **파일만 지우고 기록은 남기므로** 이 경로는 쓰이지 않습니다.
그런데 보호자가 "이 그림 지워 주세요"라고 할 때, 그 그림으로 만든 이야기를
함께 지우는 것이 보통의 기대에 가깝습니다.

**[DrawTale 설계 선택]** 그림 삭제는 **두 가지로 나눕니다.**

| 무엇 | 지워지는 것 |
|---|---|
| 「원본 그림 보관 안 함」 (지금) | 그림 **파일만**. 관절 · 이야기는 남습니다 |
| 「이 그림과 이야기 모두 지우기」 (새로) | 그림 · 관절 · 이야기 · 영상 전부 |

## 5. 아이에게는 쉬운 말로 알립니다

> **[법적 요구사항]** 개인정보 보호법 제22조의2 제3항은 아동에게 알릴 때
> **이해하기 쉬운 양식과 명확하고 알기 쉬운 언어**를 쓰도록 정하고 있습니다.
> 인공지능기본법 시행령도 표시 방법에 **이용자의 나이를 고려**하도록 하고 있습니다.

법률 문구를 아이 화면에 그대로 띄우지 않습니다. 두 벌로 나눕니다.

| 보호자용 | 아이용 |
|---|---|
| 아이가 올린 그림과 생성 결과를 서비스 제공을 위해 저장합니다 | 네가 그린 그림으로 이야기를 만들어요 |
| 선택한 내용을 바탕으로 생성형 AI 가 이야기 문장을 만듭니다 | AI 가 네가 고른 것을 이야기로 이어 줘요 |
| 아이가 말한 내용은 글자로만 받고 음성은 저장하지 않습니다 | 네 목소리는 저장하지 않아요 |
| 원본 그림은 설정에 따라 24시간 안에 삭제됩니다 | 네 그림은 이야기를 만든 뒤에 지워요 |
| 생성형 AI 가 만든 결과물입니다 | **이 이야기는 AI 가 함께 만들었어요** |

마지막 줄이 **인공지능기본법 제31조의 표시**에 해당합니다.
아이 화면 · 보호자 화면 양쪽에 각각 맞는 말로 둡니다.

**아이 화면에 쓰지 않는 말**은 지금 원칙(`F-NFR-03`)을 그대로 따릅니다 —
`발달장애` `진단` `장애` 같은 말과 기술 용어, 오류 코드를 쓰지 않습니다.

## 6. 보호자 동의 화면 문구 초안

실제 화면(S-16 또는 새 화면)에서 쓸 수 있는 초안입니다.
**[법률 검토 필요]** — 항목 구분과 문구는 검토 뒤 확정합니다.

```
아이 프로필 만들기

DrawTale 은 아이가 그린 그림과 아이가 고른 내용으로
이야기와 애니메이션을 만듭니다.

■ 무엇을 받나요
  · 아이를 부를 이름 (실제 이름이 아니어도 됩니다)
  · 아이가 올린 그림
  · 아이가 고른 이야기 카드
  · 만들어진 이야기와 활동 기록

■ 무엇에 쓰나요
  · 그림에서 캐릭터와 관절을 찾는 데
  · 고른 내용으로 이야기 문장과 음성을 만드는 데
  · 만든 이야기를 다시 보여 드리는 데

■ 얼마나 두나요
  · 올린 그림 원본: 「원본 보관」을 끄면 24시간 안에 지웁니다
  · 그 밖의 자료: 프로필을 지울 때까지          [보관 기간 확정 필요]

■ 바깥으로 나가는 것
  · 아이가 고른 카드의 말과 만들어진 문장이 OpenAI 로 갑니다
    (이야기 문장 · 내용 검사 · 읽어 주는 음성)
  · 아이가 그린 그림은 바깥으로 나가지 않습니다
  · 아이 이름 · 연락처 · 계정 정보는 보내지 않습니다

─────────────────────────────────
[필수]
□ 아이의 개인정보 수집 · 이용에 동의합니다
□ 만 14세 미만 아동의 법정대리인으로서 동의합니다

[선택]
□ 아이가 말로 덧붙이는 기능을 사용합니다
   (아이가 말한 내용이 글자로 바뀌어 이야기에 들어갑니다.
    목소리는 저장하지 않습니다. 끄셔도 서비스를 쓰시는 데 지장이 없습니다)
─────────────────────────────────

동의하지 않으셔도 이야기를 만들어 볼 수 있지만,
만든 이야기를 계정에 저장할 수는 없습니다.      [검토 필요]
```

**필수와 선택을 섞지 않습니다.** 말로 덧붙이기는 **아이가 말한 내용이 외부로 나가는**
기능이므로 따로 받습니다.

## 7. 해외 서비스로 나가는 자료

> **[법적 요구사항]** 개인정보 보호법 제28조의8 은 개인정보를 국외로 이전할 때
> 정보주체에게 **이전받는 자 · 이전 국가 · 시기와 방법 · 항목 · 이용 목적 ·
> 보유 기간 · 거부 방법과 그 효과**를 알리고 동의를 받도록 하는 등의 요건을 두고 있습니다.

**핵심은 "해외 API 를 쓰느냐"가 아니라 "개인정보가 나가느냐"입니다.**

| 나가는 것 | 개인정보인가 |
|---|---|
| 아이가 고른 카드의 말 (`숲` `길을 잃었어요`) | **아닙니다.** 정해진 목록에서 고른 값입니다 |
| 만들어진 이야기 문장 | 위 카드로 만든 것이라 개인을 알아볼 수 없습니다 |
| **아이가 말로 덧붙인 내용** | **알 수 없습니다.** 아이가 무엇을 말할지 모릅니다 |

> **[법률 검토 필요]** 선택한 카드 값과 그것으로 만든 문장이
> **개인정보 국외 이전에 해당하는지** 최종 검토가 필요합니다.
> 다만 **아이가 말로 덧붙인 내용은 무엇이 들어갈지 알 수 없으므로**,
> 그대로 내보내는 구조를 기본안으로 삼지 않습니다.

**[DrawTale 설계 선택]** 말로 덧붙인 내용은 **보내기 전에 걸러냅니다.**
이름 · 전화번호 · 주소 · 학교로 보이는 내용이 있으면 그 부분을 지우거나 이야기에서 제외합니다.
자세한 규칙은 [이야기 안전 정책](이야기-안전-정책.md)에 있습니다.

## 8. DB · 코드에 필요한 최소 변경

**꼭 필요한 것과 있으면 좋은 것을 나눕니다.** 지금 DB 를 복잡하게 만들지 않습니다.

### 꼭 필요한 것

| 무엇 | 왜 |
|---|---|
| **`child_profiles` 표** | 보호자가 "우리 아이 자료만" 다룰 수 있게 하려면 아이를 나타내는 자리가 필요합니다 |
| **`guardian_consents` 표** | 동의를 받았다는 사실을 나중에 확인해야 합니다 **[법적 요구사항]** |
| **`characters.child_profile_id`** | 그림이 어느 아이 것인지 연결 |
| **아이가 말한 내용에서 개인정보를 지우는 함수** | OpenAI 로 나가기 전 단계 |
| **AI 가 만들었다는 표시** | **[법적 요구사항]** 인공지능기본법 제31조, 이미 시행 중 |

```
child_profiles
  id · user_id(보호자) · nickname · story_level
  is_under_14 · created_at · updated_at

guardian_consents
  id · guardian_user_id · child_profile_id
  consent_type · consent_version
  agreed_at · withdrawn_at · verification_method
  created_at · updated_at
```

`verification_method` 에는 **방법의 이름만** 남깁니다. 확인에 쓴 번호나 신원 정보는 남기지 않습니다.

### 있으면 좋은 것 (나중에)

| 무엇 | 왜 미루나 |
|---|---|
| 보호자용 「저장된 정보 보기」 화면 | 데이터를 모을 API 가 먼저 필요합니다 |
| 동의 판(version) 관리 화면 | 판이 하나일 때는 필요 없습니다 |
| 자료 보관 기간 자동 삭제 | 기간부터 정해야 합니다 ([02 7-3](../02-system-architecture.md)) |

### 하지 않는 것

| 무엇 | 왜 |
|---|---|
| 주민등록번호 · 신분증 저장 | 근거가 없고, 지킬 것만 늘어납니다 |
| 아이 생년월일 전체 저장 | 만 14세 미만 여부만 알면 됩니다 |
| 진단명 · 장애 유형 저장 | **민감정보이고 서비스에 필요하지 않습니다** |
| 쓰지 않는 자료를 "나중에 쓸까 봐" 저장 | 최소 수집 원칙에 어긋납니다 |
