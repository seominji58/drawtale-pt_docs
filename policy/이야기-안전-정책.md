# 이야기 안전 정책

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (초안) |
| 작성일 | 2026-10-12 |
| 근거 확인일 | 2026-10-12 |

> **이 문서는 무엇인가**
>
> AI 가 만든 이야기가 **아이에게 해롭지 않도록** 하는 규칙입니다.
> 지금 흐름(`F-STY-04` · `F-STY-05`)을 바탕으로, 무엇을 더 둘지 정합니다.
> 자료가 어디로 가는지는 [데이터 처리 지도](데이터-처리-지도.md)에 있습니다.

**한 가지 검사를 넣었다고 안전이 끝나지 않습니다.** 여러 겹으로 둡니다.

---

## 1. 지금 어떻게 돌고 있나

```
아이가 고른 네 칸
      ↓
입력 검사        OpenAI omni-moderation-latest
      ↓
이야기 생성      카드만: 미리 만들어 사람이 읽은 것 (그때 만들지 않음)
                 덧붙임 · 보호자 입력: Claude Opus 5.5 · gpt-4o-mini + 규칙이 담긴 지시문
      ↓
결과 검사        OpenAI omni-moderation-latest  (같은 검사를 한 번 더)
      ↓
이야기 완성
```

걸리면 이야기를 만들지 않고 `CONTENT_BLOCKED` 로 돌려보냅니다.
**다른 것이 실패해도 이야기는 나오지만, 이 검사만은 예외입니다** (`F-NFR-06`).

---

## 2. 지금 구조의 빈 곳

| 무엇 | 왜 문제인가 |
|---|---|
| `omni-moderation` 은 **일반적인 유해성**을 봅니다 | 폭력 · 성적 내용 · 혐오는 잡지만, **아이에게만 문제가 되는 것**은 잡지 못합니다 |
| 무서운 내용 | "괴물이 쫓아왔어요"는 유해하지 않지만 아이에게는 무섭습니다 |
| 슬픈 결말 | 해결되지 않고 끝나면 아이에게 남습니다 |
| 따라 하면 위험한 행동 | "높은 곳에서 뛰어내렸어요"가 그대로 나갈 수 있습니다 |
| 어려운 문장 | 지시문에 "15~25자"를 넣었지만 **지켜졌는지 확인하지 않습니다** |

## 3. 여러 겹으로 둡니다

```
아이가 고른 카드 · 말로 덧붙인 내용
      ↓
① 고를 수 있는 것을 미리 제한             카드는 정해진 44장 중에서만 · 카드 이야기는 사람이 미리 읽음
      ↓
② 개인정보 거르기                        말로 덧붙인 내용에서 이름 · 연락처 제거
      ↓
③ 입력 검사                              omni-moderation
      ↓
④ 지시문으로 범위를 좁혀 생성              아래 4장
      ↓
⑤ 결과 검사                              omni-moderation
      ↓
⑥ 아이 기준 확인                          아래 5장
      ↓
   안전하면 → 이야기 완성
   아니면   → 다시 쓰거나 틀 문장으로
```

**카드 경로에서는 ①이 가장 강한 안전장치입니다.** 아이가 고르는 것이 정해진 카드뿐이라
애초에 위험한 입력이 거의 들어오지 않습니다.

### 말하기 경로에는 ①이 없습니다

이야기를 만드는 길은 두 가지입니다 ([03 5.4](../03-feature-spec.md)).

| 단계 | 카드 경로 | **말하기 경로** |
|---|---|---|
| ① 고를 수 있는 것을 제한 | 카드 44장 · **이야기도 미리 검토** | **없음** |
| ② 개인정보 거르기 | 덧붙인 말만 | **말한 내용 전부** |
| ③ 입력 검사 | 함 | 함 |
| ④ 지시문으로 범위 좁히기 | 함 | **더 중요** — 말한 것을 그대로 쓰지 않고 규칙 안에서 엮는다 |
| ⑤ 결과 검사 | 함 | 함 |
| ⑥ 아이 기준 확인 | 함 | 함 |

**가장 강한 장치가 빠지므로 나머지를 더 촘촘히 둡니다.**
말하기 경로를 **보호자가 켜야만 쓸 수 있게 한 것**(F-SET-06)도 그 때문입니다.

> 어른이 아이 말을 듣고 **대신 말하는 방식**이라, 어른이 한 번 거르는 단계가 사실상 ①을 일부
> 대신합니다. 다만 그것에만 기대지 않습니다.

## 4. 이야기를 만들 때 지키는 규칙

지금 지시문에 들어 있는 것과, 더 넣을 것입니다.

| 규칙 | 지금 | 더할 것 |
|---|---|---|
| 정확히 네 문장 | 있음 | |
| 한 문장 15~25자 | 있음 | **지켜졌는지 확인** (6장) |
| 초등 1학년이 아는 낱말만 | 있음 | |
| 주인공은 「나」, 말투는 「~어요」 | 있음 | |
| 무섭거나 슬픈 결말 금지 | 있음 | |
| **아이가 고르지 않은 위험한 상황을 넣지 않기** | | **추가** |
| **갈등이 있어도 해결되는 범위로** | | **추가** |
| **아이에게 죄책감을 주지 않기** | | **추가** |

마지막 세 가지가 중요합니다. 아이가 「길을 잃었어요」를 골랐을 때,
AI 가 "무서운 아저씨가 따라왔어요" 같은 것을 **스스로 덧붙이지 않도록** 못 박아야 합니다.

## 5. 아이 기준으로 한 번 더 봅니다

`omni-moderation` 이 통과시킨 뒤에도 아래를 봅니다.

| 분류 | 무엇을 보나 | 걸리면 |
|---|---|---|
| **HARM** | 폭력 · 다침 · 피 · 죽음 · 무기 · 성적 내용 · 욕설 · 혐오 | 이야기를 만들지 않습니다 |
| **FEAR** | 귀신 · 괴물이 쫓아옴 · 버려짐 · 납치 | 이야기를 만들지 않습니다 |
| **SAD_END** | 결말이 슬프거나 해결되지 않음 | 이야기를 만들지 않습니다 |
| **DANGER** | 따라 하면 위험한 행동 (불, 높은 곳, 모르는 사람 따라가기) | 이야기를 만들지 않습니다 |
| **PERSONAL** | 이름 · 주소 · 학교 · 전화번호 | 이야기를 만들지 않습니다 |
| **HARD** | 한 문장이 25자를 넘거나 어려운 낱말 | **다시 씁니다** (6장) |

**위반이 아닌 것:** 문제가 생겨도 해결되는 이야기.
「길을 잃었다가 도움을 받아 길을 찾았어요」는 괜찮습니다.
갈등 자체를 없애면 이야기가 되지 않습니다.

### OpenAI Teen Safety Policy 와의 관계

OpenAI 가 공개한 청소년 안전 정책은 **노골적인 폭력 · 성적 콘텐츠 · 위험한 행동과 챌린지 ·
유해한 신체 이미지 · 부적절한 역할극 · 연령 제한 상품 · 미성년자 성적 콘텐츠 ·
자해 관련 콘텐츠**를 위험 영역으로 둡니다.

위 분류는 그것을 **DrawTale 의 이야기 생성에 맞게 좁힌 것**입니다.
우리는 자유 대화가 아니라 **정해진 카드로 네 문장을 만드는 서비스**라
역할극이나 연령 제한 상품 같은 영역은 애초에 생길 수 없습니다.

> **OpenAI 도 이 정책이 완전한 해결책이 아니라 출발점이라고 밝히고 있습니다.**
> **「이 정책을 적용했으니 아동 안전 문제가 해결되었다」고 쓰지 않습니다.**

## 6. 걸렸을 때 어떻게 하나

| 분류 | 어떻게 |
|---|---|
| **HARD** (어려운 문장) | **막지 않습니다.** 한 번 더 쉽게 쓰게 한 뒤 다시 봅니다. 그래도 걸리면 **틀 문장**을 씁니다 |
| 그 밖의 분류 | 이야기를 만들지 않고 `CONTENT_BLOCKED` 로 돌려보냅니다 |

**틀 문장**은 아이가 고른 네 칸을 그대로 이어 붙인 것입니다.

```
오늘 나는 숲에 갔어요. 그런데 길을 잃었어요.
그래서 나는 달려갔어요. 그랬더니 길을 찾았어요.
```

AI 가 다듬은 것보다 오히려 짧고 쉽습니다. **아이 입장에서는 이야기가 나오지 않는 것보다 낫습니다.**

### 아이에게 보이는 문구

```
막혔을 때      이야기로 만들 수 없는 내용이 있어요. 다른 것을 골라 볼까요?
틀 문장일 때    (따로 알리지 않습니다 — 아이에게는 그냥 이야기입니다)
```

**어떤 분류에 걸렸는지 아이에게 알리지 않습니다.** 「폭력적인 내용이 있습니다」 같은 말은
아이에게 자기 잘못으로 느껴집니다 (`F-NFR-03`).

## 7. 검사가 실패하면

| 무엇이 실패 | 어떻게 |
|---|---|
| `omni-moderation` 호출 실패 | **이야기를 만들지 않습니다.** 이것이 마지막 안전망입니다 |
| 아이 기준 확인(5장) 호출 실패 | **이야기는 진행합니다.** moderation 은 이미 통과했습니다. 기록에 남깁니다 |

두 번째를 통과시키는 이유는, **아이 기준 확인이 moderation 위에 덧붙인 것**이기 때문입니다.
그것 하나가 멈췄다고 서비스를 세우지는 않습니다. 다만 **자주 실패하면 알 수 있도록** 기록합니다.

기록에는 **분류 이름 · 판정 · 걸린 시간만** 남기고 **검사한 글 자체는 남기지 않습니다.**

## 8. AI 가 만들었다는 표시

> **[법적 요구사항]** 인공지능기본법 제31조 제2항은 생성형 AI 로 만든 결과물에
> 그 사실을 표시하도록 하고 있으며 **2026년 1월 22일 시행되었습니다.**
> 시행령은 표시가 **이용자가 명확하게 인식할 수 있는 방식**이어야 하고
> **주된 이용자의 나이를 고려**하도록 합니다. (확인일 2026-10-12)

| 어디 | 문구 |
|---|---|
| 아이 화면 (이야기 보기 S-09) | **「이 이야기는 AI 가 함께 만들었어요」** |
| 보호자 화면 (설정 · 목록) | 「고른 내용을 바탕으로 생성형 AI 가 이야기 문장과 음성을 만들었습니다」 |

**[법률 검토 필요]** 어느 화면에 어떤 형태로 두어야 충분한지는 확인이 필요합니다.
음성에도 표시가 필요한지, 영상에 넣어야 하는지가 아직 분명하지 않습니다.

## 9. 쓰는 모델

| 무엇 | 어디에 |
|---|---|
| `omni-moderation-latest` | 입력 · 결과 검사 (지금 쓰는 중) |
| `gpt-4o-mini` | 짧은 이야기 (덧붙임 · 보호자 입력일 때) |
| **Claude Opus 5.5** | 긴 이야기 대본 (덧붙임 · 보호자 입력일 때). 아이 문장 56개 안전 판정 시험에서 56/56 — **판정에는 아직 쓰지 않음** ([16](../16-프론트-백엔드-작업-정리.md)) |
| 아이 기준 확인 | **아직 정하지 않았습니다** — 아래 |

아이 기준 확인(5장)을 **무엇으로 할지는 정해지지 않았습니다.**
`gpt-4o-mini` 에 규칙을 주고 판정하게 하는 방법, 별도 안전 모델을 쓰는 방법,
규칙 기반으로 글자 수와 낱말만 보는 방법이 있습니다.

**HARD(어려운 문장)는 모델 없이도 확인할 수 있습니다.** 문장 수와 글자 수를 세면 됩니다.
그것만 먼저 넣고 나머지는 뒤에 붙이는 것도 방법입니다.

> **별도 안전 모델 서버를 반드시 두지는 않습니다.** 다만 **그렇다고 안전 검사를 빼지는 않습니다.**
> 모델을 쓰든 규칙으로 하든, 5장의 분류를 확인하는 단계는 둡니다.
